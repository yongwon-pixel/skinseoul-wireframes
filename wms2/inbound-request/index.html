State 1 Changes — New Inbound Request (Smart Buy)

  1. 1New Inbound Request screen — the single intake gateway for everything entering the warehouse. Not just Smart Buy restocks: Wholesale and Brand Partnership inbounds are requested here too — I Inbound Request
  2. 2Channel (sourcing route) selection — 4 radio cards (Smart Buy / Wholesale / Brand Partnership / Other — type the channel name when selected). Badge styling matches View Orders (black bold, no colors) — I Inbound Request
  3. 3Inbound No. auto-assigned — no input field or preview on the request form (panel removed 2026-07-26). On registration, YYYYMMDDNNNN (NNNN 0001–9999 per day) is assigned automatically and shown only in the Request List. Maps to sheet column A "PO No. (=Order ID)" — named Inbound No. so it also fits inbounds without a PO — I + J
  4. 4Field set = aligned to the PH sheet column order: Inbound No. (auto) → Channel → SKU No. → Brand → Product Name → Order Qty → Unit Cost (KRW) → JIT Price (KRW) → Supplier. SKU·Brand·Product Name are locked in via the unified search; no Size — PH sheet
  5. 5Single unified search box (2026-07-27 UX improvement — one box above the table instead of per-row search) — type whichever one you know of SKU No. · brand · English product name for autocomplete; clicking a result adds a row to the table below with SKU·Brand·Product Name all auto-filled — I + F autocomplete
  6. 10Unit Cost (KRW) required — the placeholder and the disclaimer at the table's top right (position moved 2026-08-03) state it is the "actual per-unit purchase price from the supplier" (fixes the what-goes-here confusion). 0 is allowed (free-of-charge stock) — kept required as the basis of FIFO costing and sheet consistency — sheet Unit Cost column
  7. 11JIT Price (KRW) optional — per-unit price when buying via Coupang JIT. The placeholder says "leave blank if unknown" — zero input burden — sheet JIT Price column
  8. 12Supplier required — the label and placeholder (e.g. 비엠유통, Coupang) clarify it means "who is shipping the goods". Kept required as the basis for settlement and inbound tracking — sheet integration
  9. 6The product you just picked is added as a blue-tinted row — only Order Qty and Unit Cost are left to fill. SKU No.·Brand·Product Name come from the search selection and can't be edited (borderless plain-text display) — to change them, delete the row with ✕ and search again. Multiple SKUs = keep selecting in the search box (the separate "add row" button is retired); remove mistaken rows with ✕ — I Inbound Request
  10. 7Tracking No field — optional (dashed border), can be added later after dispatch. Single register button (unified 2026-07-27) — with or without a tracking number, the request registers as REQUESTED; if one is provided, View Orders matching activates immediately — I Inbound Request
  11. 8Expected arrival — lets the center see the inbound schedule ahead of time — I Inbound Request
  12. 9View Orders link note — entering a tracking number matches the request to View Orders → scans show the sourcing route badge (the link info modal was removed 2026-08-03) — I + C View Orders
  13. 14Top-right Comments hub — Comments tagged on requests (@Mentions/★Saved). Same component as View Orders + full comment search (newest first) — 0. UI 2
  14. 15Reduced side margins — the whole form fits on one screen without scrolling — C screen conventions
  15. 16New page tabs [New Request | Request List] (added 2026-07-23) — in-admin tabs switching between the request form and the request list (separate from the wireframe's purple state tabs). Pick a route and submit in New Request; view by status and add tracking numbers in Request List — I Inbound Request

Behavior rules (off-screen): Received Date and Carrier are recorded automatically at inbound and shown in the Request List (not form inputs); tracking numbers are added later in the admin. The Request List is the data the Google Sheet (Procurement Hub) will later scrape as-is — sheet integration design happens separately as the last step (agreed 2026-07-23). All labels standardized to "Comments" (never a localized label).

State 3 Changes — Request List (Requested / Partial / Inbounded)

  1. 1Status filter chips — All / REQUESTED / PARTIAL / INBOUNDED, 3 statuses (SHIPPED retired 2026-07-27 · PARTIAL added 2026-08-02). Whether tracking is entered is read from the Tracking No column, not the status — I Inbound Request
  2. 2Bulk bar (pinned above the table) — bulk add tracking numbers for selected rows. INBOUNDED transitions happen automatically via View Orders scans (the mark-shipped button is retired) — I + C bulk-bar conventions
  3. 3Sourcing Route column — SMART BUY / WHOLESALE / PARTNERSHIP badges — styled like View Orders (black bold, no colors) — I Inbound Request
  4. 4Tracking No column — an "Add tracking" button (M1 modal) when empty; when filled, the number list (multiple allowed) + matching status — I Inbound Request
  5. 5Status column — REQUESTED → PARTIAL (auto-switch when View Orders saves a partial inbound · remaining n/m shown) → INBOUNDED, 3 stages (confirmed 2026-08-02). Rescanning the same tracking number resumes reconciliation from the remainder. Expected qty edits (View Orders M6) show an edit history in the Qty cell (e.g. 300→180) + a Slack alert to the requester — I Inbound Request
  6. 6REQUESTED + no tracking = add it later via the "Add tracking" button (M1). Automatic once-a-morning check — requests still in REQUESTED without a tracking number are flagged on Slack: WHOLESALE·SMART BUY → #wholesale-ops, PARTNERSHIP → #partnership-kr (the channel for Other routes will be decided during development) — 2026-07-27 alert spec
  7. 7REQUESTED + tracking entered — multiple tracking numbers can be registered per request (split shipments, confirmed 2026-08-03) and every registered number is a View Orders match/scan target. The status badge stays REQUESTED — I + C View Orders
  8. 8INBOUNDED = auto-switched by a View Orders scan inbound (the separate link modal and result link were removed 2026-08-03 — the status badge is enough) — I + C View Orders
  9. 9Inbound automation note — INBOUNDED transitions happen from View Orders scans, not from this screen; scans surface the sourcing route badge — I + C View Orders
  10. 10Received Date column — the View Orders scan time is recorded automatically on INBOUNDED (maps to the sheet's Received Date column); not-yet-inbounded rows show "–". Automatic Carrier recording is not supported — no Carrier column (confirmed 2026-08-03) — sheet integration
