State 1 Changes — OK Scan (outbounded)

  1. 1Closing-dedicated large barcode scan input — scan the carrier-handover tracking number of today's packed orders to verify (e.g. YUN Express uses the YT prefix — YT2618100710108810). Outbound status is judged the instant it is scanned. The scanner's auto-Enter submits → verdict → focus returns with all text selected, repeating for continuous scanning. Scanner protocol: a barcode scanner types the number followed by an automatic Enter. During continuous scanning the cursor must always stay in this scan input, and the page must never refresh between scans — every scan lands in this same input with no extra clicks (shared with View Orders scan protocol) — F Closing
  2. 2OK-scan confirmation = compact one-line bar (green: sequence · order · tracking · status · time · worker). A large panel appears only on the State 4 completion screen — the large OK and warning panels were both removed (2026-07-23); warnings are read in the row, announced by the voice alert — F Dean · reworded 2026-08-03
  3. 3Voice alert toggle (on by default) — plays "Please check this order" automatically on warnings, so warnings register without watching the screen during fast scanning. A Test voice button is provided — F Dean
  4. 4Closing progress counts — outbound target (manually entered value) / OK / warnings / remaining scans + a progress bar (green OK · red warning segments) — F Closing
  5. 5OK scan = only orders whose status is Prepare Shipment → green "Outbounded". Every other status (Processing etc.) is a warning (replaces the current closing step "check whether it was outbound-processed") — F Closing
  6. 6Scan list — OK (green tint) / warning (red tint) rows, leftmost # = scan sequence # (line number). Duplicate warnings state which scans collide by # (e.g. #3 ↔ #2). Sorted lowest to highest, new scans append at the bottom. The ✕ on the right of each row = delete scan row (confirm modal "Remove this scan? Yes / No") — for clearing mis-scans and unknown orders; deleted rows are excluded from the counts (M2) — F Closing
  7. 7Comments hub in the top bar — @Mentions + Saved + full comment search (newest first), aggregating the communication trail of closing exceptions — 0. UI 2
  8. 8Confirm Closing button — enabled only when OK-scan count = the manually entered outbound target (exact match; over-scan is also a mismatch) + 0 warnings. Enabled ≠ auto-confirmed; closing requires the click (scanning stays possible after the match — finding an extra disables it again). Confirming saves the closing record — the admin's Closing History replaces the retired Daily Shipping Status spreadsheet (owner decision 2026-08-03) — F Closing
  9. 9Reduced side margins — every column + status fits on one screen without scrolling — C Screen (common)
  10. 10Today's outbound target manual count — the value entered at closing start (State 0) is shown locked. [↺ Edit count] edits the target; [✕ Cancel Closing] cancels today's closing session (returns to the pre-start screen; discarding scan records requires confirmation). The baseline is the physical count, not a system figure — F Closing
  11. 11Top menu [Closing | Closing History] — Closing History switches to a separate page (not a modal): daily snapshots · CSV export. See the "5 · Closing History" tab above for details — F Closing

Behavior rules (off-screen): the scan input is disabled until closing starts (manual count entered). After closing starts, clicking anywhere on the page auto-focuses the scan input (all text selected) for continuous scanning, and results show as a top-right toast without a reload — implemented purely as behavior, with no on-screen copy. The scanned tracking number's order status is looked up instantly → Prepare Shipment = OK (green · silent); any other status (Processing etc.) or a tracking number already scanned today (duplicate) = warning (red · voice). Closing confirm condition = OK-scan count exactly matches the manually entered outbound target + 0 warnings (over-scan is also a mismatch). Reaching the match only enables the Confirm button — it is not auto-closing: a person must press [Confirm Closing] after checking that everything was scanned, and the scan input stays alive after the match, so an extra parcel (an 85th) flips it to a mismatch warning and disables the button again. Outbound in Process Processing Order (M1) is a real order-status change reflected on every screen. A tracking number with no matching order = "unknown order" warning (State 2b) — excluded from the closing count. Closing progress is stored server-side — leaving for another page and coming back, or refreshing, keeps the count, scan list and warnings intact; nothing clears until closing is confirmed or explicitly restarted. Continuous scanning: the scanner's automatic Enter substitutes for pressing Scan (no button click needed), and right after the verdict the cursor returns to the scan input with the text fully selected — the next scan overwrites the previous value, so any number of scans run without interruption. The scanner types the number followed by an automatic Enter; during continuous scanning the cursor must always stay in this scan input, and the page must never refresh between scans — every scan lands in this same input with no extra clicks (shared with View Orders scan protocol).
