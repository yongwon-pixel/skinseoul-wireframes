# Global Rules (Draft for planning — becomes `_global-rules` spec page)

All 8 screen specs reference these by ID. Deltas only in page specs.

- **[G-1] Scanner protocol** — A barcode scanner types the number followed by an automatic Enter. During continuous scanning the cursor must always stay in the scan input and the page must NEVER refresh between scans. Every scan lands in the same input with zero extra clicks. Applies to every scan surface (View Orders, Closing). (2026-08-03)
- **[G-2] No-refresh + confirmation toast** — No full-page refresh after any action (exception: Bulk Outbound on RTO refreshes after completion, by design). EVERY confirming action (register / confirm / cancel / send / save) shows a top-right toast confirming what happened, green for success. (2026-08-03, owner emphasis: applies across all 8 screens)
- **[G-3] Audio feedback** — (a) Outbound-class buttons play a synthesized "send" sound (Web Audio, no external files). (b) Closing scan warnings speak "Please check this order" (en-US TTS) so staff hear problems without watching the screen. (2026-08-03)
- **[G-4] Instant, carrier-agnostic print** — Any Print button outputs the correct carrier's label IMMEDIATELY on click — no new tab, no browser print dialog, regardless of carrier (Deleo, YUN, or any future carrier). Requires a local print agent (PrintNode-class) that routes to the printer queue. (2026-08-03, owner: "no excuses later")
- **[G-5] Sourcing routes** — Exactly 4: SMART BUY / JIT (purchase channel in parentheses: Coupang·Naver·Other retail) / WHOLESALE / PARTNERSHIP. Rendered as colorless black bold text labels (no colored pills). Origin = Inbound Request (I); consumed by View Orders badges and Inventory.
- **[G-6] Product naming** — English name always prefixed with the brand in bold. Korean product names also carry the EN brand in bold (e.g., **Dr.Jart+** 포어레미디…). RTO "Ready Item Details" and the picking list use KOREAN names — pickers locate items faster in Korean (2026-08-03). Korean names, carrier names (CJ대한통운 등), and Korean company names are data and stay Korean in an English UI.
- **[G-7] Comments system** — Per-order comment history accumulates in admin (AI-training asset). @mention notifies the mentioned person via Slack with order no., text, time, author. Top-right Comments hub on every screen: [@ Mentions] + [★ Saved] + full-text search across ALL comments (order no./author/text), newest first, click opens the order. Badge = unread count. Mention notification channel: see `_slack-routing` (one item pending owner decision).
- **[G-8] Data-capture doctrine** — Every operator action is persisted with actor + timestamp + entity + old/new values (inbound/outbound/cancel, qty edits, location changes, closing confirmations, audit adjustments, comment posts, imports, sample assignment changes). If staff did it, admin recorded it. UI logs are views over persisted events, never the only copy.
- **[G-9] Idempotency** — Inbound/Outbound and all confirming actions must be double-click-safe: client debounce + server idempotency key (known current bug: double-click processes twice — must be fixed).
- **[G-10] Multiple tracking numbers per inbound request** — An inbound request may register several tracking numbers (split shipments). EVERY registered number matches in View Orders and enters the internal-inbound screen (State 6). (2026-08-03)
- **[G-11] Inbound request lifecycle** — REQUESTED → PARTIAL (n/m remaining, amber) → INBOUNDED. Expected-qty edits allowed with mandatory reason (supplier change / damaged / other), recomputes gating, notifies requester via comment + Slack. Unrequested arrivals route to the shared unrecognized pool.
- **[G-12] Deep links** — Cross-page references are real links (e.g., View Orders State 6 banner → `../inbound-request/#reqlist` opens the Request List tab). In the real admin they deep-link to the filtered entity.
- **[G-13] Sample assignment (Order Management)** — Simple ON/OFF with multi-period support; exactly 1 sample set per order even with overlapping periods. Dual-view: carrier-facing data only appends "(+ sample set)" to the last product name (tax); internal invoice & picking label show WHICH sample and HOW MANY. (07-23 redesign, 08-03 reconfirmed)
- **[G-14] Location scheme** — One location per SKU. Inventory location filter groups by line (A/B/C…), line list derived dynamically from registered locations. Audit-mode-only UI stays hidden outside audit mode. (2026-08-03)
